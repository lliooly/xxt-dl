# 刷题模式可靠性修复设计

## 背景

当前刷题模式已经具备章节练习、全部练习、错题复习和结果页，但练习模块没有自动化测试覆盖。只读排查确认了三类可稳定复现的问题：

1. 填空题没有输入控件；同时通用答案归一化会删除绝大多数中文字符，即使输入与正确答案完全相同也会判错。
2. 单选题在已答题与未答题之间切换时，把 `RadioGroup` 的 `value` 从字符串切换为 `undefined`。Base UI 会在首次渲染时确定受控模式，因此控件可能保留上一题选择；新题正确选项与旧题相同时，再次点击不会触发提交。
3. 错题复习结果页的“再来一轮”调用普通题库的 `createSession`。该函数不处理 `wrong-book` 模式，因而生成空会话，也不会重新读取当前错题本。

此外，错题数在仪表盘中通过空依赖 `useMemo` 只读取一次。组件重新挂载时通常会刷新，但这种隐式行为不足以保证所有从练习页返回的路径都显示最新数据。

## 目标

- 填空题可输入、提交并按文本答案判定。
- 单选题、多选题和填空题在换题、跳题、重来时不继承其他题目的草稿或选择状态。
- 错题复习完成后，“再来一轮”基于当时最新的待复习错题重新创建会话。
- 从练习或错题本返回仪表盘时，错题数量立即反映本地存储的当前状态。
- 为练习引擎和关键状态转换补充回归测试。

## 非目标

- 本次不引入 SQLite，也不改变错题本的 localStorage 存储格式。
- 不实现主观题 AI 判分、模糊语义判分或多空拆分编辑器。
- 不重写整个练习界面状态架构。
- 不改变“答对错题仅增加复习次数、由用户手动标记掌握”的现有产品语义。

## 方案选择

### 方案 A：定向修复状态边界（采用）

保留现有组件结构，拆出可测试的题型和答案归一化规则；让答题控件始终受控，并让错题会话从最新存储重新建立。改动集中、兼容现有数据，也能针对三个根因建立回归测试。

### 方案 B：以 reducer 重写整套练习状态

可统一管理题目、草稿、提交和导航，但涉及所有练习组件，风险与验证成本明显高于当前缺陷范围。

### 方案 C：仅用 React `key` 强制重挂载题卡

可以暂时清掉选项残留，但不能提供填空控件、修复中文判题或重建最新错题会话，只能处理表面症状。

## 详细设计

### 题型与答案判定

`quiz-engine` 根据题型采用不同归一化策略：

- 选择题：保留现有的大写字母、数字和判断符号归一化，多选题继续做集合等价比较。
- 填空题及无选项题：保留 Unicode 文字和数字，去除首尾空白，并统一内部连续空白及常见全角空白；不删除中文。
- 空字符串始终判错。

第一阶段只做单个文本答案的精确比较，不把分号解释为多个可接受答案，避免猜测来源数据的语义。

### 题卡输入状态

题卡按题目类型渲染：

- 多选题使用复选框和显式确认按钮。
- 有选项的非多选题使用单选组。
- 填空题或没有选项的题目使用文本输入和显式“提交答案”按钮。

单选组始终传入字符串 `value`，未作答时使用空字符串，绝不切换到 `undefined`。填空草稿和多选草稿在题目身份变化时重置为当前题目的已提交答案或空值。题目身份由章节 ID 与题号共同确定，避免不同章节相同题号互相污染。

### 会话与错题刷新

普通会话仍由 `createSession` 从章节题库构建。错题会话始终由 `createSessionFromQuestions` 构建。

`PracticeView` 提供统一的“按当前来源创建新一轮”逻辑：普通模式按原配置重新抽题；错题模式在点击时重新调用 `getWrongEntriesForReview()`，再创建错题会话。如果当前已无待复习错题，则返回错题本或仪表盘，不生成空会话。

仪表盘通过显式的刷新版本或直接读取属性获得错题数量。每次退出练习、进入错题本或结束一轮练习时更新版本，避免依赖组件是否恰好重新挂载。

### 错误处理

- 文本输入仅包含空白时禁用提交。
- 创建会话得到零题时保持当前页面，不进入不可操作的空结果页。
- localStorage 数据损坏继续沿用现有容错策略，视为空错题本。

## 测试设计

新增练习引擎测试，至少覆盖：

- 中文填空答案与自身比较为正确，空白答案为错误。
- 填空答案忽略首尾空白和连续空白差异。
- 多选题仍保持顺序无关且集合严格相等。
- 提交答案只更新目标题，换题后的未作答题保持空状态。
- 错题会话工厂每次使用传入的最新题目集合。
- 普通会话、下一题、跳题、结果统计行为不回归。

组件层通过构建检查和本地浏览器验证以下路径：

1. 填空题输入、提交、结果展示和下一题。
2. 连续两道答案相同的单选题可以分别点击作答。
3. 已答题与未答题之间来回跳转，选择显示与题目状态一致。
4. 错题复习结束后新增或移除错题，“再来一轮”读取最新集合。
5. 返回仪表盘后错题数立即更新。

## 验收标准

- 用户列出的三个问题均有稳定复现证据、对应修复和回归验证。
- `npm run check`、`npm test`、`npm run build` 全部退出码为 0。
- 浏览器手动流程覆盖填空、换题状态和错题新一轮刷新。
- 不改动或提交用户已有的 `next-env.d.ts` 工作区变更，也不提交 `output/` 课程资料。
