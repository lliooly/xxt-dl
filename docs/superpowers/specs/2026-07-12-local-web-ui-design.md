# XXT DL 本地 Web UI 设计

## 背景

当前界面由 Next.js 渲染，但首页在浏览器启动后直接访问 Electron preload 注入的 `window.xxt`。普通浏览器不存在该对象，因此页面无法作为纯 Web 应用正常运行。项目已经具备 Playwright 采集逻辑、题目导出文件和初步刷题组件，本次改造需要在保留这些业务能力的同时移除 Web UI 对 Electron 的运行时依赖。

## 目标

- 通过本地 Next.js Web 应用完成学习通登录、课程选择、作业抓取和题目整理。
- 通过同一 Web 应用读取本地 `output/*.questions.json` 并完成刷题练习。
- 保留现有 Playwright、`.xxt-profile`、`output`、CLI 和 Electron 源码，避免破坏已有功能。
- 修复组件无法渲染、浏览器白屏和窄屏布局溢出问题。

## 非目标

- 不支持公网部署或多用户并发。
- 不实现自动提交学习通作业或考试答案。
- 不实现 Electron 自动更新、安装包下载或重启安装的 Web 替代品。
- 不在本次改造中引入 SQLite、云同步或 Telegram Bot。

## 架构

Web 页面不再读取 `window.xxt`，而是通过本地 Next.js API 控制下载任务：

```text
Web 页面
  -> /api/download/start
  -> 本地下载任务服务
  -> Playwright 登录与采集
  -> .xxt-profile / output

Web 页面
  -> /api/download/state
  <- 状态、二维码、课程、进度、日志

Web 页面
  -> /api/download/course 或 /api/download/stop
  -> 选择课程或终止任务

Web 刷题页面
  -> /api/practice-chapters
  -> output/*.questions.json
```

下载任务服务复用现有采集逻辑，并提供与传输协议无关的启动、停止、选课和状态查询接口。Electron 可以继续使用原有入口；Web API 不直接复制解析或抓取规则。

第一版只允许一个本地活动任务，避免多个标签页同时控制同一个浏览器 profile。每次启动生成任务 ID，修改任务的请求必须携带匹配的任务 ID。

## 页面与组件

首页保留两个主入口：

1. **作业整理**：运行状态、扫码登录、课程选择、抓取进度、错误提示、运行日志和完成结果。
2. **刷题练习**：章节选择、随机刷题、答题反馈、结果页和错题本。

`app/page.tsx` 只负责页面导航和组合，下载工作台、任务状态展示等职责拆入独立组件。Web UI 删除版本更新、安装包下载、取消更新和重启安装等 Electron 专属内容。

全局布局取消固定的 `900px` 最小宽度。主要双栏区域在宽屏显示两列，在窄屏按单列排列。空题库、未启动任务、等待扫码、请求失败和任务完成都提供明确状态，不允许因浏览器 API 缺失而白屏。

继续使用仓库现有的 Tailwind、shadcn/Base UI 和 lucide-react，不引入新的组件框架。

## 状态与数据流

服务端任务快照包含：

- `taskId`
- `status`
- 二维码信息
- 课程列表
- 当前进度
- 完成结果
- 错误信息
- 有界日志列表

前端启动任务后约每秒轮询状态。活动任务结束后停止高频轮询；用户重新启动或刷新页面时可从状态接口恢复当前任务视图。

任务状态只保存在本地 Node.js 进程内，不持久化 Cookie、验证码信息或额外课程内容。二维码接口只返回显示所需信息，不返回浏览器 profile 内容。

## API 行为

- `POST /api/download/start`：启动任务；已有活动任务时返回冲突错误。
- `GET /api/download/state`：返回当前任务快照；无任务时返回空闲状态。
- `POST /api/download/course`：为匹配的任务提交课程选择。
- `POST /api/download/stop`：停止匹配的活动任务并释放浏览器资源。
- `GET /api/practice-chapters`：继续读取本地结构化题目文件。

重复启动、任务 ID 不匹配、课程选择无效和内部异常应返回合适的 HTTP 状态码与可直接展示的中文错误信息。

## 错误处理

- Playwright 或采集异常写入任务快照并显示在页面中。
- 停止任务时关闭浏览器上下文，避免残留 Chromium 进程。
- 前端网络请求失败时保留当前界面，显示可重试错误，不清空已有进度。
- 单个损坏的题目 JSON 文件继续跳过，不阻止其他章节加载。

## 测试与验收

采用测试驱动开发：先为任务状态、并发约束、任务 ID 校验和 API 行为编写失败测试，再实现最小代码使其通过。

自动验证：

- `npm run check`
- `npm test`
- `npm run build`

界面验收：

- 普通浏览器打开首页时不访问 `window.xxt`，页面无白屏。
- 下载和刷题组件均能正常显示。
- 窄屏下不出现由固定最小宽度造成的整体横向溢出。
- 下载任务能够进入等待登录、课程选择、抓取、完成、停止或错误状态。
- 无 `output` 题库时显示空状态，存在题库时可以开始练习。

实际学习通扫码登录依赖用户账号和网络环境，自动验证完成后由用户进行最终手动确认。
